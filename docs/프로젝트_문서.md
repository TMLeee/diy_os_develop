# DIY OS 프로젝트 문서

MINT64 OS를 기반으로 한 64비트 멀티태스크 운영체제 프로젝트의 설계 문서입니다.
BIOS가 로딩하는 512바이트 부트로더에서 시작해, 보호 모드(32비트)를 거쳐
최종적으로 **IA-32e(롱) 모드**의 64비트 커널까지 부팅합니다. 산출물은 1.44MB
플로피 이미지(`Disk.img`)이며 **QEMU**에서 실행합니다.

```
16비트 부트로더 ──► 32비트 보호 모드 커널 ──► 64비트 IA-32e 커널
 (Bootloader)          (Kernel32)                (Kernel64)
  섹터 로딩            메모리/CPU 확인,           GDT/IDT/TSS,
  0x7C00              페이지 테이블 생성          키보드/PIC/PIT/RTC,
                                                 콘솔 셸, 멀티태스킹
```

빌드/실행/디버깅 상세는 리포지터리 루트의 [README.md](../README.md)를 참고하세요.

## 1. 프로젝트 개요

### 무엇을 만드는가

- **MINT64 OS 기반의 64비트 운영체제**를 밑바닥부터 구현하는 학습용 프로젝트입니다.
- x86 CPU는 전원이 켜지면 16비트 리얼 모드로 시작하므로, 보호 모드(32비트)를
  거쳐 IA-32e(롱) 모드의 64비트 커널까지 단계적으로 부팅합니다.
- 산출물은 1.44MB 플로피 이미지(`Disk.img`)이며 QEMU에서 실행합니다.

### 현재 구현된 기능

| 분류 | 기능 |
| --- | --- |
| 부팅 | 16 → 32 → 64비트 모드 전환, 커널 이미지 디스크 로딩 |
| CPU/메모리 | CPUID로 64비트 지원 확인, 최소 64MB 메모리 검사, 총 RAM 크기 측정 |
| 세그먼트/인터럽트 | GDT, TSS, IDT 초기화 및 IST(인터럽트 전용 스택) 구성 |
| 인터럽트 처리 | PIC 컨트롤러 초기화·마스킹, ISR 핸들러, 예외 핸들러 |
| 입력 | PS/2 키보드 인터페이스, 키보드 큐, LED 제어 |
| 타이머/시계 | PIT(카운터), RTC(날짜·시간), TSC(타임스탬프 카운터) |
| 콘솔 | 텍스트 화면 출력(`kPrintf`), 커서 제어 |
| 셸 | 명령어 파싱 및 실행 콘솔 셸 |
| 멀티태스킹 | TCB 기반 태스크 컨텍스트 정의 및 컨텍스트 전환(`kSwitchContext`) |

### 콘솔 셸 명령어

`console_shell.c`의 명령어 테이블에 등록된 명령들입니다.

| 명령 | 설명 |
| --- | --- |
| `help` | 도움말 출력 |
| `cls` | 화면 지우기 |
| `totalram` | 총 RAM 크기 출력 |
| `strtod` | 문자열 → 10진수/16진수 변환 테스트 |
| `shutdown` | 종료 및 재부팅 |
| `settimer` | PIT 카운터0 설정 `settimer 10[ms] 1[periodic]` |
| `wait` | PIT를 이용한 지연 `wait 100[ms]` |
| `rdtsc` | 타임스탬프 카운터 읽기 |
| `cpuspeed` | 프로세서 속도 측정 |
| `date` | 현재 날짜·시간 출력 |
| `createtask` | 테스트 태스크 생성 후 컨텍스트 전환 데모 |

### 실행 환경

- **툴체인**: Cygwin(`make`, `nasm`, `gdb`) + `x86_64-pc-linux` 크로스 컴파일러
- **실행**: 번들된 QEMU 0.10.4 (`qemu-0.10.4/`)
- **디버깅**: 최신 QEMU + gdb 스텁 + VS Code C/C++ 확장 (F5)

```bash
make            # Bootloader + Kernel32 + Kernel64 + Utility + Disk.img
qemu-0.10.4/qemu-x86_64.bat   # 부팅
```

## 2. 프로젝트 구조

### 디렉터리 구성

```
10.OS/
├── 00.Bootloader/        16비트 부트로더 (NASM)
│   └── Bootloader.asm    BIOS가 0x7C00에 로딩, 커널 이미지를 디스크에서 적재
│
├── 01.Kernel32/          32비트 보호 모드 커널 (C + ASM)
│   └── src/
│       ├── EntryPoint.s  16→32비트 모드 전환 진입점
│       ├── main.c        메모리/CPU 확인, 64비트 커널 복사, IA-32e 전환
│       ├── page.c/.h     페이지 테이블 생성
│       ├── mode_sw.asm   IA-32e 모드 전환 어셈블리
│       └── types.h       기본 타입 정의
│
├── 02.Kernel64/          64비트 IA-32e 커널 (C + ASM) — 핵심 커널
│   └── src/
│       ├── EntryPoint.s        64비트 커널 진입점
│       ├── main.c              커널 초기화 및 부팅 시퀀스
│       ├── descriptor.c/.h     GDT · TSS · IDT 구성
│       ├── isr.asm             인터럽트 서비스 루틴(ISR) 스텁
│       ├── interrupt_handler.c 인터럽트/예외 핸들러
│       ├── pic.c/.h            PIC 컨트롤러 제어
│       ├── keyboard.c/.h       PS/2 키보드 인터페이스
│       ├── queue.c/.h          범용 큐 (키보드 버퍼 등)
│       ├── pit.c/.h            PIT (Programmable Interval Timer)
│       ├── rtc.c/.h            RTC (실시간 시계)
│       ├── console.c/.h        텍스트 화면 출력·커서
│       ├── console_shell.c/.h  콘솔 셸 (명령어 파싱/실행)
│       ├── task.c/.h           태스크 제어 블록(TCB)·컨텍스트
│       ├── utility.c/.h        메모리 함수, kPrintf, RAM 측정 등
│       ├── assembly_utils.asm  포트 I/O, 인터럽트 제어, 컨텍스트 전환
│       └── types.h             기본 타입 정의
│
├── 03.Application/       응용 프로그램 (예정)
├── 04.Utility/
│   └── 00.ImageMaker/    디스크 이미지 생성 도구 (ImageMaker.c)
│
├── qemu-0.10.4/          번들 QEMU (실행용)
├── ImageMaker.exe        빌드된 이미지 생성기
├── Disk.img             빌드 산출물 (1.44MB 플로피 이미지)
└── makefile             전체 빌드 오케스트레이션
```

### 빌드 파이프라인

```
Bootloader.asm ─nasm─► Bootloader.bin ┐
Kernel32 소스  ─gcc/ld─► Kernel32.bin  ├─ ImageMaker.exe ─► Disk.img ─► (1.44MB로 패딩)
Kernel64 소스  ─gcc/ld─► Kernel64.bin  ┘
```

루트 `makefile`이 각 하위 디렉터리의 `make`를 순서대로 호출하고,
`ImageMaker.exe`가 세 바이너리를 하나의 부팅 이미지로 병합한 뒤
표준 플로피 크기(1,474,560바이트)로 패딩합니다.

### 3단계 커널 구조 이유

x86 CPU는 전원이 켜지면 **16비트 리얼 모드**로 시작합니다. 64비트
롱 모드로 곧바로 진입할 수 없기 때문에 단계적으로 전환합니다.

1. **Bootloader (16비트)** — 최소한의 코드로 나머지 커널 이미지를 메모리에 로딩
2. **Kernel32 (32비트 보호 모드)** — 메모리·CPU 확인, 페이지 테이블 준비 후 64비트 커널을 메모리에 복사
3. **Kernel64 (64비트 IA-32e)** — 실제 운영체제 기능이 동작하는 본체

## 3. 부팅 과정

CPU는 리얼 모드(16비트)로 부팅하므로 64비트 모드까지 3단계로 전환합니다.

```
① BIOS
   └─ 부트 섹터(512B)를 0x7C00에 로딩하고 실행

② Bootloader (16비트 리얼 모드)  — 00.Bootloader/Bootloader.asm
   ├─ 세그먼트/스택 초기화 (SS=0x0000, SP=0xFFFE)
   ├─ 화면 초기화 및 부팅 메시지 출력
   └─ 디스크에서 커널 이미지(Kernel32+Kernel64)를 0x10000에 로딩
       · TOTAL_SECTOR_SIZE, KERNEL32_SECTOR_SIZE 로 크기 관리
       └─ Kernel32 진입점으로 점프

③ Kernel32 (32비트 보호 모드)     — 01.Kernel32/src/main.c
   ├─ 최소 메모리 검사 (64MB 이상, kCheckMemSizeOvr64MB)
   ├─ IA-32e 커널 영역 초기화 (1MB~6MB를 0으로 클리어)
   ├─ IA-32e용 페이지 테이블 생성 (kInitPageTbl)
   ├─ CPUID로 프로세서 벤더 및 64비트 지원 여부 확인
   ├─ 64비트 커널(Kernel64)을 0x200000(2MB)로 복사 (kCpy64KernelToMem)
   └─ IA-32e 모드로 전환 후 64비트 커널로 점프 (kJump64BitKernel)

④ Kernel64 (64비트 IA-32e 모드)   — 02.Kernel64/src/main.c
   ├─ 콘솔 초기화
   ├─ GDT + TSS 구성 및 로드   (kInitGDTTableAndTSS / kLoadGDTR / kLoadTR)
   ├─ IDT 구성 및 로드         (kInitTDTTable / kLoadIDTR)
   ├─ 총 RAM 크기 확인         (kCheckTotalRAMSize)
   ├─ 키보드 인터페이스 활성화 (kInitializeKeyboard)
   ├─ PIC 초기화 · 인터럽트 활성화 (kInitializePIC / kEnableInterrupt)
   └─ 콘솔 셸 시작            (kStartConsoleShell)
```

### 커널 이미지가 메모리에 놓이는 순서

부트로더는 커널 전체 이미지를 `0x10000`에 연속으로 적재합니다. 이후
Kernel32가 자신보다 뒤쪽에 있는 Kernel64 부분만 떼어 `0x200000`으로
복사합니다. 복사 크기는 부트로더가 `0x7C05`(총 섹터 수), `0x7C07`
(Kernel32 섹터 수)에 기록해 둔 값으로 계산합니다.

```
0x10000 ┌────────────────────┐
        │ Kernel32 (32비트)  │  ← 여기서 실행
        ├────────────────────┤
        │ Kernel64 (64비트)  │  ── 복사 ──►  0x200000 (2MB)에서 실행
        └────────────────────┘
```

## 4. 메모리 구조

MINT64 OS의 물리 메모리 배치입니다. 낮은 주소가 아래쪽, 높은 주소가
위쪽에 오도록 그렸습니다(그림 18-4와 동일한 방향).

### 전체 메모리 배치도

```
     높은 주소
        ▲
        │        . . . . . .
0x1100000 (17M) ├───────────────────────────────────┐
        │        . . . . . .                          │
        │  ┌────────────────────────────────┐         │
        │  │            스택 풀             │  ◄─ 8KB × 1024(최대 태스크 수) = 8MB
        │  └────────────────────────────────┘         │
        │  ┌────────────────────────────────┐         │
        │  │            태스크 풀           │  ◄─ sizeof(TCB) × 1024 < 1MB
0x800000 (8M)  └────────────────────────────────┘     │
        │  ┌────────────────────────────────┐
        │  │  IA-32e 모드 커널 IST 영역     │  (인터럽트 전용 스택, 1MB)
0x700000 (7M)  ├────────────────────────────────┤
        │  │  IA-32e 모드 커널 스택 영역    │
0x600000 (6M)  ├────────────────────────────────┤
        │  │                                │
        │  │     IA-32e 모드의 커널 영역    │  (Kernel64 코드/데이터)
        │  │                                │
0x200000 (2M)  ├────────────────────────────────┤
        │        . . . . . .
        │  ┌────────────────────────────────┐
        │  │  IA-32e 모드의 커널 자료구조   │  (GDT/TSS/IDT/페이지 테이블)
0x100000 (1M)  └────────────────────────────────┤
        │        . . . . . .
        │  ┌────────────────────────────────┐
        │  │  부트 로더 영역과               │
        │  │  보호 모드 커널 영역            │  (Bootloader + Kernel32)
0x7C00  ├───────────────────────────────────┤
        │                                    │
   0    └────────────────────────────────────┘
     낮은 주소            메모리 공간
```

### 영역별 설명 (설계 기준 배치)

| 주소 | 영역 | 설명 |
| --- | --- | --- |
| `0x00000` | 실모드 벡터/스택 | BIOS 인터럽트 벡터, 부트로더 실모드 스택(SP=0xFFFE) |
| `0x07C00` | 부트로더 | BIOS가 로딩하는 512바이트 부트 섹터 |
| `0x10000` | 커널 이미지 적재 | 부트로더가 Kernel32+Kernel64를 연속 로딩 |
| `0x100000` (1M) | IA-32e 커널 자료구조 | GDT/TSS/IDT, 페이지 테이블 등 |
| `0x200000` (2M) | IA-32e 커널 영역 | 64비트 커널(Kernel64) 코드·데이터 |
| `0x600000` (6M) | 커널 스택 영역 | 64비트 커널 실행 스택 |
| `0x700000` (7M) | IST 영역 | 인터럽트 전용 스택(Interrupt Stack Table), 1MB |
| `0x800000` (8M) | 태스크 풀 | 최대 1024개 TCB 저장, `sizeof(TCB) × 1024 < 1MB` |
| 이후 | 스택 풀 | 태스크별 스택, `8KB × 1024 = 8MB` |

### 코드로 확인되는 실제 주소 상수

현재 소스에 하드코딩/정의된 주소들입니다.

| 상수 / 위치 | 주소 | 출처 |
| --- | --- | --- |
| 부트로더 로딩 | `0x7C00` | BIOS 규약 (`Bootloader.asm`) |
| 커널 이미지 적재 | `0x10000` | `01.Kernel32/src/main.c` `kCpy64KernelToMem` |
| 커널 영역 클리어 범위 | `0x100000` ~ `0x600000` | `kInitKernel64Area` (1MB~6MB를 0으로) |
| `GDTR_START_ADDR` | `0x142000` | `02.Kernel64/src/descriptor.h` |
| IDTR/IDT | `GDTR_START_ADDR` 뒤에 연속 배치 | `descriptor.h` (GDTR+GDT+TSS 다음) |
| IA-32e 커널 복사 대상 | `0x200000` | `kCpy64KernelToMem` (목적지 2MB) |
| `IST_START_ADDR` | `0x700000` | `descriptor.h`, 크기 `IST_SIZE = 0x100000` |
| 비디오 메모리 | `0xB8000` | `console.h` `CONSOLE_VIDEO_MEM_ADDR` |
| RAM 크기 측정 상한 스캔 | `0x4000000`(64M)부터 4MB 단위 | `utility.c` `kCheckTotalRAMSize` |

> **참고 — 태스크/스택 풀의 현재 상태**
> 위 배치도의 `0x800000` 태스크 풀 / 스택 풀은 MINT64의 **최종 설계
> 목표 배치**입니다. 현재 `add_multitask` 브랜치의 멀티태스킹은 아직
> 풀을 물리 주소에 배치하지 않고, `console_shell.c`에서 정적 배열로
> 태스크와 스택을 잡아 컨텍스트 전환을 시연합니다.
> ```c
> static TCB_t  gtTask[2]     = {0,};   // 태스크 제어 블록
> static QWORD  gqwStack[1024] = {0,};  // 태스크 스택 (8KB)
> ```
> 태스크 풀(`0x800000~`)과 스택 풀 배치는 이후 태스크 관리자
> 구현 단계에서 위 배치도대로 이전될 예정입니다.

### 태스크 컨텍스트(TCB) 구조

`task.h`에 정의된 태스크 제어 블록입니다. 컨텍스트 전환 시 24개
레지스터(세그먼트 5 + 범용/제어 19)를 스택에 저장·복원합니다.

```c
typedef struct kTaskControlBlockStruct {
    Context_t tContext;      // 레지스터 컨텍스트 (24 × 8바이트)
    QWORD     qwID;          // 태스크 ID
    QWORD     qwFlag;        // 플래그
    void*     pvStackAddr;   // 스택 시작 주소
    QWORD     qwStackSize;   // 스택 크기
} TCB_t;
```

컨텍스트 전환은 `assembly_utils.asm`의
